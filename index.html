01 — Problem + constraints

Users needed better questions. The form still had to work without AI.

People describing a legal issue may not know which details an attorney needs. AI could surface missing context, but latency and output were uncertain.

Role
Senior Product Designer
Timeline
8 weeks
Platform
Responsive web
Team
Product + Engineering

The existing intake already collected a case description and area-specific answers. The opportunity was to ask only for context that was still missing.

The base intake had to remain complete when the model returned no questions or timed out.

Existing flowKeep Areas of practice (AOP) questions, contact details, email, and dashboard.
Bounded outputReturn 0–2 optional questions after Next.
Safe failureNever turn AI latency into user work.
AI could add context, but never block submission.
Core product rule · assistance remained optional to the system
02 — Flow architecture

One bounded AI layer sat inside the working intake.

After the existing AOP questions, Next triggered a short analysis step. Every branch converged on the same contact and send flow.

Guardrails · 100 characters before Next · 0–2 optional questions · five-second timeout · AI never blocks submission

03 — Three product decisions

The prototype reduced how much AI users had to notice or recover from.

01 / SUPPLEMENT

AI followed the intake instead of replacing it.

After Next and a 100-character description, a text-only “Analyzing your case details…” state could return 0–2 optional questions.

02 / READINESS

Next and Submit stayed in the document flow.

The prototype made the non-sticky actions clearer because they no longer implied the request was ready too early.

Image needed: sticky vs non-sticky CTA before/after (Figma export pending)
03 / FALLBACK

At five seconds, AI disappeared quietly.

On timeout, the analysis section collapsed and contact fields moved up. The base intake continued without an error or retry.

→

Silent collapse · no error · no retry · submission remains available

04 — Message delivery

The richer message stayed in the attorney’s existing workflow.

Only answered follow-ups were appended. The user’s description remained primary, and attorneys kept receiving the result through the same email and dashboard.

05 — If not me

The interface might have signaled “ready” before the form was ready.

My intervention

Turn the prototype into a product decision, not a presentation artifact.

By challenging the inline AI and sticky call-to-action (CTA), I helped the team separate “write,” “clarify,” and “send” into a sequence it found clearer.

07 — What I’d do differently

Next time, I’d define message quality before drawing the screen.

01

Set the data contract first

Agree on what makes an intake actionable and map existing inputs before designing prompts.

02

Test the fallback first

Prototype the zero-question path as the default reliability case, not an edge case.
